# T07 — 持久化恢复与并发提交

Status: TODO
Blocked by: T01

依据：[架构第 6 节与 R01–R08](../../../2.ARCHITECTURE.md)、[内存设计原型](../../recovery-prototype.html)。交付真实 SQLite 与进程边界上的恢复；原型只提供设计场景。

## 验收

- [ ] R01：非法动作/步号在绑定前拒绝，无账户变化；可提交修正动作。
- [ ] R02：绑定后、读取执行资料前结束进程，重启取回原 Plan；同一步其他 request_id 冲突。
- [ ] R03：读取资料后中断，read 找回完整冻结请求、步号和恢复方式；改 ID/内容仍拒绝。
- [ ] R04：奖励暂时失败保留绑定而不提交账户；恢复原身份成功。修复导致代码/奖励身份变化时须新 run。
- [ ] R05：在提交事务中注入故障，重开库只见全有或全无的账本、响应、步号与 COMMITTED；不留下半笔扣款。
- [ ] R06：提交成功但调用方未收到响应，结束状态下同内容重试先返回原响应；即使当前计算环境不同，也不重算已提交结果。
- [ ] R07：同请求并发计算，只提交一次；成功后迟到异常不能覆盖成 PAUSED。失败记录也核对绑定、base_version 和当前状态。
- [ ] R08：原字节输入/代码/奖励/依赖身份可恢复；新身份拒绝续算，但不能因此把旧运行标为 FAILED。
- [ ] 规范内容哈希忽略目标排列与等价十进制表示，保留原始请求审计；请求声明的身份或内容变了仍冲突（A09/A18）。
- [ ] 同 run 新步不能跳过已绑定步；诊断落库失败时不声称已保存 PAUSED；read 只返回最后提交账户。

## 范围与证据

不增加 resume API、reward_pending 账本或持久化 READ/CALCULATED。必要的故障入口仅用于测试，不暴露为用户功能。保留真实子进程退出点、临时库检查、并发结果和公开响应证据；重复执行稳定后标 DONE。
